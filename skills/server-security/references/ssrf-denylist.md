# SSRF 出站目标拒绝清单

> 由 `server-security` skill 的 §9 引用。任何"由用户提供 URL 或域名"的服务端出站请求，都必须过这张表。

## 1. 协议白名单

- 只允许 `http`、`https`。
- MUST 拒绝：`file`、`gopher`、`dict`、`ftp`、`ldap`、`jar`、`netdoc`、`mailto`、`data`、`blob`，以及任何自定义 scheme。
- MUST 拒绝带 userinfo 的 URL（见第 4 节）。

## 2. IPv4 拒绝网段

| 网段 | 含义 |
|---|---|
| `0.0.0.0/8` | 本网络（可映射到本机） |
| `10.0.0.0/8` | 私有 |
| `100.64.0.0/10` | CGNAT / 运营商内部 |
| `127.0.0.0/8` | 回环 |
| `169.254.0.0/16` | 链路本地 / 云元数据（**最关键**） |
| `172.16.0.0/12` | 私有 |
| `192.0.0.0/24` | IETF 协议分配 |
| `192.0.2.0/24` | 文档示例 |
| `192.88.99.0/24` | 6to4 中继（历史） |
| `192.168.0.0/16` | 私有 |
| `198.18.0.0/15` | 基准测试 |
| `198.51.100.0/24` | 文档示例 |
| `203.0.113.0/24` | 文档示例 |
| `224.0.0.0/4` | 组播 |
| `240.0.0.0/4` | 保留（含 `255.255.255.255`） |

## 3. IPv6 拒绝网段

| 网段 | 含义 |
|---|---|
| `::/128` | 未指定地址 |
| `::1/128` | 回环 |
| `::ffff:0:0/96` | IPv4 映射（**可绕过 IPv4 校验**） |
| `64:ff9b::/96` | NAT64（可映射到内网 IPv4） |
| `100::/64` | 丢弃前缀 |
| `2001:db8::/32` | 文档示例 |
| `2002::/16` | 6to4（内嵌 IPv4） |
| `fc00::/7` | 唯一本地地址（私有） |
| `fe80::/10` | 链路本地 |
| `ff00::/8` | 组播 |

## 4. URL 解析陷阱（每一种都是真实绕过手法）

1. `http://allowed.com@evil.com/` —— userinfo 混淆，实际主机是 `evil.com`。
2. 十进制 / 八进制 / 十六进制 IP：`http://2130706433/`、`http://0177.0.0.1/`、`http://0x7f000001/`。
3. 末尾点：`http://evil.com./`、`http://127.0.0.1./`。
4. IPv6 方括号变体：`http://[::ffff:127.0.0.1]/`、`http://[0:0:0:0:0:ffff:7f00:1]/`。
5. 协议相对与反斜杠：`//evil.com`、`http:\\evil.com`、`http:///evil.com`。
6. 大小写与 Unicode 混淆：`http://EVIL.com`、`http://еvil.com`（西里尔字母）。
7. 短链与多级跳转：短域名 → 302 → 内网地址。
8. DNS rebinding：校验时解析为公网 IP，连接时重新解析为内网 IP。
9. `Host` 头与 URL 不一致（虚拟主机绕过）。
10. 超长 URL / 超深路径导致解析器截断或差异解析（解析器不一致分歧）。

## 5. 云元数据端点（按云厂商标配覆盖）

| 云 | 端点 | 备注 |
|---|---|---|
| AWS / Azure / GCP / OpenStack | `169.254.169.254` | 最常见，IMDSv1 无鉴权 |
| AWS（IPv6） | `fd00:ec2::254` | 双栈环境易漏 |
| GCP | `metadata.google.internal` | 主机名形式，需同时按名称与 IP 拦 |
| 阿里云 | `100.100.100.200` | 落在 CGNAT 段 |
| 腾讯云 | `169.254.0.23` / `metadata.tencentyun.com` | 链路本地段 |
| Oracle Cloud | `192.0.0.192` | 协议分配段 |

## 6. 校验与连接的正确顺序

1. 解析 URL，取出 host（不信任任何 userinfo、端口写法）。
2. 解析 DNS，得到**全部** A / AAAA 记录；任一落入拒绝清单即拒绝。
3. **固定已校验的 IP 用于连接**（pin IP，或在 HTTP 客户端设置解析回调），避免二次解析被 rebinding 利用；同时保留原 `Host` 头。
4. 每一跳重定向都必须重复 1–3 步；重定向次数上限（建议 ≤ 3），或直接禁用重定向。
5. 设置连接 / 读取超时、响应体大小上限、并发上限；禁止流式无限读取。
6. 出站流量尽量走受控出口代理，并在代理侧再做一次目的地校验。
7. 记录出站目标（脱敏后）与拒绝原因，便于发现探测行为。
